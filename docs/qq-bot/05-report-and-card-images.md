## 2. 推荐实现链路

```text
QQ /七日报告 或 /密探卡 司马徽
  → 插件固定事件身份与选中子账号，检查对应图文读取授权
  → 后端组装固定展示数据，创建临时 snapshot 并返回短期授权 URL
  → 插件中的浏览器打开网站 /bot/snapshot/:snapshotId
  → 页面使用短票据读取该 snapshot，复用前端 report/card 组件及统计函数
  → 等待字体、图片、组件就绪，截取目标容器 PNG
  → AstrBot 经 NapCat 发给原 QQ 私聊
```

前端维护模板、样式和统计呈现；后端负责授权与数据；插件负责浏览器生命周期、取图和消息投递。插件运行浏览器截图，后端 Kotlin 不新增截图微服务。

前端新增专用 snapshot 路由，跟随 YuanHub 正常构建部署，直接复用源组件；插件不用部署独立渲染包。路由仅消费专用 API 返回的 JSON，不把用户数据拼成脚本/HTML。

渲染页面不加载完整账号中心，不登录网站，不接收 JWT、长期 Bot Token 或服务凭证；仅使用 120 秒 snapshot_ticket 读取固定的 snapshot 数据接口。插件以长期授权创建短票据，每次渲染独立页面/上下文，防止上一个账号的数据、localStorage 或状态残留。

Playwright 支持元素截图和内存图片缓冲区，适合此链路：[官方截图文档](https://playwright.dev/python/docs/screenshots)。AstrBot 支持图片消息：[官方消息发送文档](https://docs.astrbot.app/dev/star/guides/send-message.html)。本期确定的是组件复用与私有数据通道；依赖版本、浏览器安装和图片组件参数按实施环境核验。

## 3. 七日报告的数据与口径

现有网页 7d 为“今天及前 6 个自然日”，不是最近 168 小时。前端按浏览器本地日期计算，接口区间为起始日 00:00 到结束日次日 00:00 的 `[from,to)`。QQ 默认 `Asia/Shanghai`，图片明确标注日期、时区、生成时间；浏览器上下文使用同一时区以复用 localDayKey。对比网页时必须选择相同时区和区间。

报告不能仅用 acquired 总量代替，需准备：

- item 和 agent 的时段 acquired 总量，仍以后端 reward_delta 聚合为权威。
- 七日内的流水记录，包含 acquisition_channel、stamina_cost、effective_at、transaction_id、entries 等现有 DTO 字段。
- 截至区间终点的 agent 历史流水，供“久未回响”等依赖更早历史的指标使用。
- 该子账号的特别关注 agent_ids，以及公共目录/头像和名称。
- 明细/历史是否完整、各数据源是否可用等状态。

现有页面对明细分页最多整理 5,000 条，并明确提示截断；历史查询也单独标记完整性。机器人初版沿用同样边界与提示，不能只读第一页，也不能把“历史不足”当成“从未获得”。统计函数只把 reward_delta 当作获得量；库存快照不纳入累计奖励。

数据查询中途出现部分源错误，可使用组件已有“不可用/不完整”呈现；权威汇总失败不得显示成 0，全部失败则不给出看似完整的报告。时间段内无数据时输出真实空报告。

## 4. 单个密探卡的数据与呈现

- 按公共目录解析唯一 operator_id，读取该授权子账号 game 下已保存的 current entry，沿用 universal 回退等已有规则。
- 保留卡片的核心排版、攻生自动/手动及 stale 状态、奇闻、等级/化极、两套命盘和六槽星石的展示语义。
- 提供该密探已保存的 annotation（养成状态、备注）及关注标记所需数据；明确图文授权描述包含这些字段。
- 卡片展示服务器已保存状态，不携带浏览器未提交草稿、输入框、操作弹窗、保存按钮或提交遮罩。只读形态仍复用卡片组件，不能用整个编辑页面截图代替。
- 材料扣除/升级弹窗不属于卡片图片，不为截图调用任何写接口。
- 未招募或没有当前养成资料时明确回复无对应养成卡，不能拿公共图鉴默认值冒充用户实际养成。
- 图片页眉标注子账号和游戏版本，主体只包含目标密探；不渲染整个账号的其他密探数据。

## 5. 权限与接口增补

新增两项推荐的只读 Bot 权限，**不自动扩大已有 current read 的数据范围**：

| scope | 授权页文案及范围 |
| --- | --- |
| `inventory:report:read` | 查看库存报告：读取奖励流水、时段汇总和特别关注名单，用于七日报告 |
| `operator:card:read` | 查看密探养成卡：读取已保存养成、状态、备注及关注标记 |

二者可单独授权；不依赖写权限，也不要求普通 OpenAPI export 权限。它们仅用于 Bot 数据读取，不改变现有普通 OpenAPI 的权限目录、特别关注 JWT 规则或交流档案字段。只有对应数据路由实现后才列入 Bot 权限目录。已有连接新增功能时由用户主动保存授权，不后台补 scope。

数据组装按两个 kind 实现，授权范围如下；HTTP 统一通过 snapshot 创建/读取/销毁接口交付，不再另加两条未实施的 views 路由：

| kind | scope | 数据职责 |
| --- | --- | --- |
| `inventory_weekly`，params.end_date 可省略 | inventory:report:read | 计算上海时区近七日区间，组装汇总、两类流水/完整性、关注和必要目录数据 |
| `operator_card`，params.operator_id 必填 | operator:card:read | 仅包含目标密探 current、已保存 annotation、关注标记与必要目录数据 |

snapshot 数据响应共同包含 `snapshot_id, expires_at, kind, account_id, account_name, game, generated_at, data`。weekly 另含 `timezone, from, to, end_date`。`data` 按上述真实组件依赖定义具名 DTO，正式实施时与前端抽出的 presenter 输入一一对应并展开到 OpenAPI；不能将任意原始账号文档装进 Map 透传。密探精确字段映射需在抽出组件时核对每个使用的函数，不能声称 current 一项已经足够。完整 HTTP 与票据边界见 snapshot 页面方案。

后端可复用现有查询及分页组织数据；不在新端点直接重算前端“偏爱指数”等展示公式。单次报告明细/历史各保留上限与完整性字段，不引入大导出任务队列。

## 6. 出图与发送要求

- `/七日报告`、`/密探卡 名称` 为显式按需回复；“直接发给用户”本期表示图片消息，不自动增加定时群发或订阅。
- 图文授权不足时提示到网页开启对应能力，不绕用登录 Cookie/分享链接；失败时不在其他 QQ 或群里发送。
- 截图前等待字体、必要图片与组件 ready；为静态输出关闭入场动画/懒加载阻塞，不能截 loading 或透明未进入视口的卡片。
- 长报告按模块分页为多张可读 PNG，标明页码；不把超长图片缩到文字看不清。卡片按目标容器截图。
- AstrBot 与 NapCat 分离容器时，插件本地文件路径未必可被 NapCat 读取。采用适配器支持的图片字节/base64 交付并实测，或明确受控共享卷；不能默认 file:// 路径跨容器可用。
- 私有报告不上传公开 `/media` 或公开图床，不创建永久公开分享链接。图片临时数据在发送完成/失败后清理；浏览器上下文及时关闭，配置小的并发上限及超时即可。
- 渲染开始时固定子账号、权限和数据；发图前复查对应授权仍有效。中途切账号不改图的归属，撤权后丢弃尚未发送的图。
- 渲染失败可明确说明失败并提供已授权的文字查询入口，不能把文字回退记录成图片验收成功。

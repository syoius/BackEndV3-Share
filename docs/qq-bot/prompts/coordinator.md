```text

1. D0 文档已编写；验证当前代码实际状态，不能把方案标为实现。

跨端对齐重点：
- botInstance 来自服务凭证，sender 来自消息事件；内部用户/子账号不是模型参数。
- 两个绑定入口共享网页最终 confirm；确认前不签发有效凭证。
- 后端 Token 类型隔离；普通 OpenAPI/JWT 不能替代 Bot 通道，Bot Token 不能绕回普通 API。
- 连接位于主账号，grants/Token 位于子账号；未授权名称展示默认关闭，且不允许访问内容。
- scopes 使用共享契约，UI 只展示已实现能力；新建账号不自动授权。
- 插件可恢复领取原 Token；撤权/解绑/账号删除/换发后旧凭证失效。
- 写预览固定账号、对象和 payload；重复确认只写一次，revision 冲突重新预览；正常账号切换不改变已有操作。
- 新接口的实际 OpenAPI、字段、错误、权限与客户端一致。
- 七日报告复用 acquiredStats.js，近七个自然日/时区、关注、历史完整性及分页截断都与网页一致；养成卡复用已保存状态，原网页编辑不退化。截图页只拿对应 snapshot 的 120 秒短票据，不拿登录 Cookie 或长期凭证；验证票据到期/撤权/目标隔离、无登录启动、ready/error，不假定 AstrBot 与 NapCat 共享文件路径。

进度规则：
- 只在 00-overview-and-progress.md 维护总状态，记录日期、仓库/提交或文件、测试命令及结果、待办和下一步。
- 状态分未开始、进行中、已实现待联调、已验收、阻塞；测试/部署环境缺失写具体事实。
- 前端或插件只输出回填记录时，核对证据后再更新，不凭“已完成”一句话勾选。
- 有契约调整时先更新 01-contract.md 和受影响方案/prompt，再同步客户端，避免三份不同 API 定义。需要产品决策才向用户提问，普通实现细节自行处理。
- 测试只针对具体失败及所需修复，不重复跑已解决的检查。涉及库存实施必须阅读仓库库存标准和 Schema。

联调使用获授权的测试 QQ、测试子账号和测试后端。若缺少地址/凭证/运行实例，索取必要信息，不要求用户把秘密贴进文档。默认不自动部署公网、不向真实用户发消息、不写生产数据；准备好可审查的具体部署材料再按实际授权执行。

最终交付：
1. 三端实现与实际检查状态。
2. 两种绑定入口、多账号权限、撤销、Token 恢复、两种写操作以及七日报告/单密探卡图片的端到端证据。
3. 明确的剩余限制/依赖和下一步。
4. 更新后的总进度与一致的接口契约。
不要用估计百分比代替完成证据，也不要把后端实现等同整个功能上线。
```

# AstrBot + NapCat 插件执行方案

状态：未实施；插件仓库与实际安装版本待实施时核验。执行入口：[插件 prompt](prompts/astrbot.md)。接口以 [共享契约](01-contract.md) 为准。

## 1. 接入与边界

使用 AstrBot OneBot v11 适配器接入 NapCat，第一版只处理私聊。AstrBot 官方文档提供了指令注册、消息事件与平台/私聊过滤方式：[消息事件](https://docs.astrbot.app/dev/star/guides/listen-message-event.html)。NapCat 与 AstrBot 的反向 WebSocket 配置及 Token 对齐参考 [OneBot 接入文档](https://docs.astrbot.app/platform/aiocqhttp.html)。参考核验日期：2026-09-10；实际插件 API 按安装版本再次确认。

本期不是通用 HTTP 代理。插件不能让用户或模型选择后端基址、任意 URL、Authorization、sender_id 或任意 scope。

## 2. 最小配置与模块

运营配置：`backend_base_url, web_base_url, bot_instance_id, expected_bot_qq, bot_service_secret`。backend/web 地址固定，由运营者配置；实例 ID 只用于本地事件路由和核对，后端仍从服务凭证决定身份。不要新增用户可配置的管理员后端 Token。

OneBot 连接凭证属于 NapCat/AstrBot 平台配置，与 bot_service_secret 分开。连接限制在本机/私网；跨公网时使用加密连接。部署说明仅写占位符和配置位置，不写真实凭证。

建议职责分离，但按插件规模选择文件数量：

- 插件入口：指令注册、事件过滤、生命周期关闭资源。
- 后端客户端：异步 HTTP、身份上下文、错误解析、凭证领取。
- 绑定处理：请求创建/兑换、短期轮询、消息回复。
- 账号与查询：授权列表、切换、目录 ID 解析、结果格式化。
- 操作处理：预览、确认/取消、稳定 request_id、超时与重投。

使用 AstrBot 约定的插件数据目录。Token 可仅在内存缓存，进程重启后按当前 QQ 从后端 resolve 恢复，无需把所有 Token 永久写入插件配置。日志、异常、聊天、模型工具参数都不含秘密。

## 3. 发送者与实例上下文

1. 先验证事件来自 OneBot、指定机器人账号、私聊，再处理指令。
2. 从事件读取 sender ID 和 self ID，按字符串传递；昵称仅用于展示。
3. 未匹配本实例的消息不使用当前实例的服务凭证。一个 AstrBot 加载多个机器人时不能共享不区分实例的 Token 缓存。
4. 缓存键包含 bot_instance_id、sender_id、account_id。群 ID、session_id、被 @ 对象和引用消息作者均不能代替发命令的人。
5. 群聊只给简短“请私聊使用”的提示，不显示绑定码、授权链接、账号名称或个人数据。

## 4. 指令设计

| 指令 | 行为 | 阶段 |
| --- | --- | --- |
| `/绑定` | QQ 起点创建授权请求，返回网页登录链接 | A1 |
| `/绑定 code` | 兑换网页创建的绑定码，提示返回网页确认 | A1 |
| `/绑定状态` | 查询该 QQ 待绑定状态，或显示已有连接状态 | A1 |
| `/账号` | 列出已授权子账号、权限、当前选择；可选列出其他名称 | A1 |
| `/切换账号 序号或名称` | 从最新授权列表解析唯一账号，调用 selection | A1 |
| `/库存 [名称]` | 查询当前账号库存；可按目录名称定位 | A1 |
| `/密探 [名称]` | 查询当前账号密探养成 | A1 |
| `/七日报告` | 复用网页近七日获得报告，返回图片 | A3 |
| `/密探卡 名称` | 复用网页目标密探养成卡，返回图片 | A3 |
| `/设置库存 名称 数量` | 对单项绝对库存生成预览 | A2 |
| `/设置密探 名称 等级 数值` | 预览 level 修改 | A2 |
| `/设置密探 名称 星级 数值` | 预览 star_level 修改，展示对应化极/星级含义 | A2 |
| `/确认 操作号` | 确认已固定的操作 | A2 |
| `/取消 操作号` | 取消自己的未执行操作 | A2 |
| `/管理授权` | 返回固定网页连接管理地址，不夹带 Token | A1 |

这些为预期命令语法，落地时检查 AstrBot 已有命令冲突，必要时增加统一命令组并同步使用说明与前端绑定提示，不能一端仍提示旧命令。

同名子账号或物品/密探须展示候选，不能猜。账号使用稳定 account_id；物品/密探从公共目录解析 `(entity_type,id)`。名称不存在时给明确提示，不能根据模糊匹配直接写入。

`/库存`、`/密探` 不带名称时可以分页或截断展示并提示如何查看余项，不能把第一条误当作全部结果。空数据、无选择和无权限分别处理。

## 5. 双起点绑定与 Token 领取

- 成功创建/兑换后在插件数据目录保存 request_id、所属实例/QQ 和 expires_at 这些短期非秘密元数据，按 3 秒间隔查询到终态或 expires_at，不无限轮询；终态后清理等待记录。
- 网页起点兑换成功后回复“已验证 QQ，请回网页确认授权”，不能提前回复绑定成功。
- QQ 起点链接由后端生成，核对其属于配置网页域；只在当前 QQ 私聊返回。
- authorized 后读取 accounts，再按需 resolve 对应账号 Token；不会把 Token 发给用户。
- resolve 响应丢失可以重试，返回原 Token，不触发自动 rotate。重启后用户 `/账号` 即可恢复，不能要求重新绑定。
- 未授权请求在插件重启后不必后台主动补发消息；用户可用 `/绑定状态`，或重新 `/绑定`。已有连接先展示管理入口，避免多余待绑定请求。
- 整条连接不存在时清理该发送者的 Token 缓存；单账号撤权只清该账号。授权 scope 以服务端判断为准，不能只信本地缓存。

## 6. 多账号与查询

`/账号` 以服务端 selected_account_id 标注当前选择，例：

```text
当前：如鸢主号
1. 如鸢主号：查询库存、查询密探
2. 代号鸢小号：查询库存、修改库存
其他子账号（未授权）：测试号
```

“其他子账号”行仅在后端实际返回时显示，不能从缓存中的历史列表补回来。切换序号按该次最新列表解析，名称重复则要求选择稳定候选；切换成功后所有回复标注账号名。

无当前选择时提示 `/账号` + `/切换账号`；不擅自选择下一账号。查询前解析当前授权，再取该账号 Token，防止网页撤权/改选择后仍用旧状态。

## 7. 修改、重试与并发

1. 解析显式写命令，检查输入是有效整数和唯一目录对象，读取当前授权/选择。
2. 从消息事件产生稳定 request_id，例如组合实例、sender、message_id；缺少稳定 message_id 时持久保存本次生成 ID 与待确认操作的关系，网络重试必须复用。
3. 调用 preview，由后端返回变化，例如“如鸢主号：白金币 103 → 120；回复 /确认 op_x”。不由模型自行拼出未经后端核验的确认结果。
4. 确认上下文固定原 account_id 和 operation_id；随后切换账号也不能把操作改到新选择。另一 QQ 或过期确认不能执行。
5. confirm 无新 payload；后端重新校验授权及 revision。返回 committed 才回复成功；冲突需要重新预览和用户重新确认。
6. confirm 网络超时可以按同 operation_id 查询式重试该 confirm，后端幂等返回；不能新建 operation/record 再自动提交。
7. 提交前撤权或换 Token，应使待确认操作失效；不要自动领取新 Token 后接续旧写操作。

插件只负责呈现用户确认，不提供超时自动确认，也不把通用“好”“嗯”当作确认。请求不同操作号必须各自明确绑定。

## 8. 自然语言增强（后续，不影响本期完成）

先用显式指令完成闭环。以后需要自然语言时，模型只能输出已允许的 operation kind 与业务字段，身份/Token 由插件从事件注入；权限检查和写确认仍走相同后端路径。绑定码与授权命令应由确定性处理器直接消费，不进入模型上下文。

## 9. 验证与交付

自动化验证聚焦：多实例/发送者缓存隔离、群消息过滤、两入口绑定状态、Token resolve 恢复、401/403 分类、撤权后停止、账号切换不改待确认操作、重复消息和 confirm 重试不新建写操作。后端 Mock 不能代替真实鉴权验收。

真实联调使用获授权的测试 QQ 和测试子账号，覆盖网页与 QQ 两个起点、多子账号不同权限、切换查询、撤权/换发/解绑、两类写操作与重复确认。没有测试 QQ 或 NapCat 运行环境时标记待联调，不发送真实用户消息冒充测试。

交付可安装插件源码及 metadata、依赖与配置 schema（按实际 AstrBot 版本要求）、安装说明、指令帮助、测试结果、总进度记录。不要为了骨架预先安装或改动生产 AstrBot/NapCat。

## 10. A3：图片查询回复

按 [报告与养成卡图片](05-report-and-card-images.md) 和 [snapshot 页面方案](06-bot-snapshot-page.md) 使用对应图文 scope 调用 POST /bot-api/v1/snapshots。后端组装固定数据并签发只读短票据 URL；插件使用 Playwright 打开该网站 URL，等待 #bot-report-root 标记 ready 后截图，使用 AstrBot 图片组件发往原私聊。

本功能复用前端模板及统计函数，不使用 AI 生图。浏览器仅拿 120 秒 snapshot_ticket，不拿长期 Bot Token、服务秘密或网页登录 Cookie；插件也不持有网站签名主密钥。出图上下文按请求隔离，固定账号，发送前复查原账号授权；图片、snapshot 和浏览器资源在结束时清理。核验 AstrBot/NapCat 分容器时字节/base64 传输，不能默认本地路径互通。长报告分模块分页，头像/字体/懒加载失败不能产生不可读的“成功图”。

部署文档说明浏览器依赖，以及访问网页深链接、后端 snapshot API 和公开素材的连通性；不再配置 render_bundle_path。snapshot_ticket 不进日志或 QQ 消息，到期只允许仍待回复且授权有效的命令重新申请一次；页面 error 状态不发图。真实收到图片、与网页同数据对比、票据/图文权限隔离均进入 A3/E3 验收；纯文本回退不能算图片功能完成。不增加定时推送订阅。

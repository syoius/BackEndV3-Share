## 2. 已确认的产品方向

- 接入 AstrBot + NapCat，面向 QQ 用户，第一版全部使用私聊。
- 网页 `/绑定 code` 和 QQ `/绑定` 两个入口，最终在登录网页明确授权。
- 连接位于网页登录主账号层；同一 QQ 可以授权该主账号的多个子账号。
- 一条连接下，每个已授权子账号独立签发 Bot 专用 Token；不占用现有普通 API Token 的配额。
- 权限按子账号配置，读取为推荐项，修改需要主动勾选。
- 网页展示所有本人子账号和授权状态；QQ 默认展示已授权子账号及 Bot 权限。
- “允许机器人查看其他未授权子账号名称”为可选项，默认关闭；展示名称不等于授予数据权限。
- 新建子账号不自动授权；撤销一个子账号不影响其他子账号；断开 QQ 撤销整条连接下所有 Bot Token。
- 授权、身份校验和 Token 处理不依赖大模型；修改需要确认具体对象、账号和变化。
- 支持把前端七日流水 report 和单个密探养成 card 作为图片回复到 QQ，复用现有组件与统计口径。
- 图片通过网站专用 `/bot/snapshot/:snapshotId` 页面渲染；后端签发仅用于该临时快照的短期票据，插件打开 URL 截图，不单独部署前端渲染包。

## 3. 本方案采用的实施默认值

这些是为使方案可执行而确定的初始规则，不是对现有实现的描述：

- 每个机器人实例内，一个 QQ 仅连接一个网页登录主账号；一个主账号仅连接一个 QQ。多个子账号不受此限制。跨主账号绑定同一 QQ 不在本期范围，不能静默覆盖旧绑定。
- 首期支持库存与密探查询；第二阶段加入“设置单项库存绝对数量”和“修改密探等级/化极（星级）”。其他写操作、导出、群聊及自然语言增强不作为本期完成条件。
- 绑定请求有效期 5 分钟；修改确认有效期 2 分钟；到期后重新发起，不自动延长。
- Bot Token 为可撤销的长期随机凭证，本期不增加自动续期协议；与普通 Token 隔离保存。服务端每次校验实际授权状态。
- 后端保存当前选中子账号；网页初次选择与 QQ 切换使用同一字段，避免两套默认账号漂移。
- 前端实际仓库已确认为 `/home/syoius/YuanHub`，已核验 profile 连接入口、AcquiredPeriodReport 和密探页面中的养成卡；详见图片方案。插件仓库路径和部署地址尚未提供。

## 5. 总体验收

| 场景 | 预期 |
| --- | --- |
| 网页起点 | 选择两个子账号 → 私聊兑换码 → 网页核对 QQ 并确认 → 插件取得两份 Token |
| QQ 起点 | 私聊 `/绑定` → 打开授权链接并登录 → 授权两个子账号 → QQ 查询成功 |
| 最终确认前 | 没有可用 Bot Token；仅打开授权链接不会自动连接 |
| 多账号隔离 | 同一 QQ 的切换只在自己的授权集合内；其他 QQ 不能使用其 Token |
| 权限隔离 | 子账号 A 只读、B 可写；切换 A 后无法借 B 的权限修改 A |
| 展示可选项 | 关闭时不返回未授权账号；开启时只返回其名称，不允许查询内容或切换 |
| 撤销 | 移除一个 grant、删除子账号、断开连接后，旧 Token 在下一次请求失效 |
| 凭证恢复 | 插件重启后可恢复已有授权，不重复创建连接或签发新 Token |
| 修改确认 | 明确目标与变化，切换账号不能改变待确认操作；重复确认只写一次 |
| 冲突 | 网页同时修改过目标时，旧预览不能覆盖新值，要求重新预览 |
| 既有功能 | MaaYuan 普通 API Token、JWT 网页访问及原库存规则保持可用 |
| 图文查询 | QQ 实际收到七日报告与单个密探卡；复用前端组件，数值、时间范围、数据不完整提示与网页一致 |

“下一次请求失效”不声称取消已经通过鉴权并正在执行的请求。

## 3. 授权选择

- 用现有 JWT 子账号列表展示所有本人子账号；用 connections/grants 标识授权状态。
- 勾选子账号后，推荐勾选“查询库存”“查询密探养成”；修改默认关闭。
- 从 `GET /v1/qq/permissions` 取得已实现能力。B2 阶段不显示不能使用的写能力；B3 完成后再开放。
- write 依赖同域 read，UI 清楚联动并解释；服务端仍负责最终验证。取消 read 时同时取消对应 write，保存前用户可见变化。
- 当前选中账号必须属于勾选的集合；取消其授权时提示重新选择，或在管理场景明确保存为无选择。
- “允许机器人查看其他未授权子账号名称”默认关闭，说明“仅展示名称，不允许访问数据”。已授权账号列表及 Bot 权限属于基本功能，无需额外勾选。
- 新建子账号不会自动勾选。页面中的“全选”只选择当前展示的账号，不代表授权以后新增的账号。

最终授权按钮前展示完整 QQ、机器人和本次选择。QQ 身份不能由输入框修改；若身份错误，取消并重新发起。注明不要授权他人转发的链接。

## 4. 两个入口的状态处理

### 网页入口

1. JWT 创建 request，展示 code，提供复制 `/绑定 code` 的按钮以及机器人 QQ。
2. 每 3 秒查询本人请求状态；离开页面/取消/终态/到期停止轮询。状态恢复以服务器 expires_at 为准。
3. 兑换成功仅表示 QQ 已验证，显示最终确认页面，不显示“连接成功”。
4. confirm 成功后重新读取 connections，显示授权结果。不要尝试领取 Bot Token。

### QQ 入口

1. 固定授权路由读取片段 request/ticket；只接受本站预期字段，不接受任意 redirect_url。
2. 未登录则走现有登录流程。短期 ticket 只为该标签页登录恢复保存，例如 sessionStorage，消费/取消/过期后删除，不放长期 localStorage。
3. 登录后用 POST claim 将 ticket 绑定到当前主账号；随后清除 URL 片段中的 ticket 和临时存储，后续凭 JWT + request_id 查询。不要把 ticket 交给埋点或错误采集。
4. 显示授权选择及最终确认。只打开页面、完成登录或 claim 均不能自动 confirm。
5. 已被他人认领、QQ 已连其他主账号、过期分别显示契约规定的错误；不能让用户在本页面覆盖旧身份。

请求已确认时重开/刷新显示既有结果，不重复创建连接。绑定请求到期后显示重新发起入口；不能通过倒计时重置来延长。

## 5. 管理与撤销

- 保存用完整 selection + expected_revision；冲突后重新载入并提示用户复核，不自动把旧表单覆盖到新状态。
- 移除子账号授权要说明“机器人将无法访问该子账号”，其他子账号不受影响。
- 清空全部 grants 可保留 QQ 连接，当前选择置空；新增授权不需要再验证 QQ。
- “重新签发机器人凭证”只调用 rotate，提示插件会自动重新取得凭证，不展示明文。
- 断开连接需确认影响范围，成功后回到未连接状态。网页错误不能提前清空界面制造成功假象。
- 删除子账号后刷新授权列表；名字变更以最新列表显示，不能按旧名称匹配授权。

## 6. API 集成与错误显示

新增薄的 QQ API 模块，复用登录 JWT 注入、刷新、超时及请求取消机制。新 QQ 接口的失败包装为 `{error:{code,message}}`，不要假定它与旧 ApiResult 失败完全相同；在局部适配，不更改所有旧接口解析。

401 登录问题走已有登录处理；409 状态冲突清楚提示；410 显示到期；429 按 Retry-After 暂停轮询。后端不可用时保留用户选择，不把网络错误解释成解绑成功。

连接管理页面与 `/bot-api/v1` 的 Token 领取或业务调用无关，只调用 JWT 管理接口。新增 snapshot 页面独立使用短票据 GET 数据，不进入登录流程。前端配置不得包含 bot_service_secret 或任何长期 Bot Token。

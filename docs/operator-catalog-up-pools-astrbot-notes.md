# AstrBot 卡池接入功能记录

日期：2026-09-09。状态：需求记录；后端接口尚未实现，本文不是可直接使用的接入手册。

完整后端方案见 [密探目录 UP 卡池与草稿发布：后端开发计划](./operator-catalog-up-pools-backend-plan.md)。本记录不涉及插件仓库代码修改。

本文只描述管理员维护公共卡池。普通用户通过 AstrBot 记录个人出金、查询单池/全池统计的能力见 [AstrBot 个人抽卡记录计划](./gacha-records-astrbot-notes.md)，使用个人子账号 Token，与本文权限分开。

## 功能范围

| 场景 | 插件输入/行为 | 后端职责 |
| --- | --- | --- |
| 新卡池公告 | 游戏、名称、北京时间起止、UP 密探 ID 或名称 | 创建卡池，复用密探或自动创建草稿 |
| 复刻公告 | 新的一次创建请求，可复用旧卡池资料 | 新 `pool_id`，保留旧历史 |
| 延期/时间修正 | 定位 `pool_id`，只传需要修改的时间字段 | 更新所有 UP 成员的卡池副本 |
| 名称或 UP 名单修正 | 一个请求可同时传名称、时间及最终成员列表 | 原子完成资料更新、成员增减、必要的草稿创建 |
| 查找已有卡池 | 按游戏、名称、时间范围查询，读取详情 | 聚合各密探中的副本，返回稳定 ID 和成员 |
| 查找密探 | 按 ID 或精确名称查询，含草稿 | 返回匹配及发布状态，避免重复创建 |

游戏仅 `如鸢` / `代号鸢`。同名卡池可能有多次开放，插件不得仅凭名称选择修改对象；有多个候选时应交给操作者指定。公告解析和采集由插件承担，后端只接收结构化数据。

## 约定

- 时间发送带 `+08:00` 的 RFC 3339 字符串，结束时间为排他边界。若公告只写日期或没有时区，插件先按明确的公告规则补齐，不自行猜一个结束时刻。
- 密探输入按 ID 或 `name` 精确匹配；不存在的名字自动创建草稿，默认稀有度 5，游戏取本次卡池游戏。后续更新优先使用返回的 ID。
- 自动创建不会发布密探。管理员在后台补齐资料并发布，插件没有发布权限。
- 密探目录是唯一来源；发布后后端的心纸目录、关注和库存导入直接识别该 ID。插件不需登记第二份库存密探目录，仍不能通过普通库存导入创建目录对象。
- `pool_id` 表示某游戏的一次开放，延期保留 ID，复刻使用新 ID。
- 修改时字段缺失表示不变，`up_operators` 提供时表示完整最终名单，不能把“新增一位”直接作为完整名单发送。
- 创建时产生稳定 `request_id`，超时或连接失败后重试使用原值和原正文；一次新的公告操作用新值。含按名称新增成员的编辑同样使用去重 ID。
- 保存响应中的 `pool_id`、密探 ID、创建/更新结果。创建请求重放返回原创建结果，最新卡池状态通过详情查询获取。
- 一次写请求整体成功或整体失败，不以部分完成作为成功上报。

## 鉴权边界

使用管理员创建的目录集成 Token，不使用个人子账号的 `operator:write` Token。后端每次检查 Token 及所属管理员的当前 `operator_catalog:write` 权限。

首版能力限于查询、新建和编辑卡池，以及附带创建最小草稿；不允许发布、任意编辑密探普通资料、删除密探或整次删除卡池。误录删除由管理员界面处理。

## 请求形状示意

以下字段以最终 OpenAPI 为准，省略具体路径和响应包裹：

```json
{
  "request_id": "astrbot:example-create-001",
  "game": "如鸢",
  "name": "示例卡池",
  "start_at": "2026-09-10T05:00:00+08:00",
  "end_at": "2026-09-24T05:00:00+08:00",
  "up_operators": [
    { "id": "char_125_zhaoyun" },
    { "name": "尚未收录的新密探" }
  ]
}
```

延期修改的正文可以只有：

```json
{
  "end_at": "2026-09-27T05:00:00+08:00"
}
```
